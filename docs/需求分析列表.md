# 生成式软件工程课程设计平台 —— 需求分析列表（V1.2）

> 版本记录
> - V1.0 初始需求列表
> - V1.1 步骤交付物改为「按步骤可配置的交付项模板」，学生按交付项逐项提交
> - V1.2 系统管理模块新增「大模型服务配置」及配置安全要求

## 一、项目概述

- 项目定位：辅助教师管理学生课程设计（逐步开发模式）的教学管理平台
- 业务核心：课程按步骤（Step）组织，每一步检查学生进度与成果并评分
- 技术栈：Spring Boot 4+（JDK 21+）/ MySQL 8+ / Vue 3 / DeepSeek API
- 开发模式：前后端分离，迭代式逐步开发
- 角色：管理员、教师、学生（凭邀请码进班）

## 二、角色与权限

| 角色 | 主要职责 |
|------|----------|
| 管理员 | 用户管理、课程模板管理、大模型服务配置、系统配置、数据维护与统计 |
| 教师 | 创建班级与邀请码、按步骤安排课程、配置交付物要求、检查成果、评分 |
| 学生 | 凭邀请码加入班级、查看步骤与交付要求、逐项提交成果、查看进度与评分 |

## 三、概念模型（核心设计）

```
班级(Class) ──< 邀请码(InviteCode) ──< 学生
课程(Course) ──< 步骤(Step)
步骤(Step)
 ├── 基本信息：标题、描述、要求、参考资料、发布时间、截止时间、权重
 └── 交付物要求列表（1~N 项，教师建步骤时配置）
       └── 交付项(DeliverableItem)：名称、类型、是否必填、类型专属约束

提交(Submission) ──< 提交项(SubmissionItem)
提交项与交付项一一对应，内容形式随类型而定（文件 / 文本 / URL）
评分(Score) 针对整次提交，可含分维度打分
```

**交付物类型字典（首期）**

| 类型 | 内容形式 | 校验约束 |
|------|----------|----------|
| 文档 | pdf/docx/md 文件 | 格式白名单、大小上限 |
| 代码压缩包 | zip/rar/tar.gz 文件 | 大小上限、可选文件数限制 |
| 源码仓库 | GitHub/Gitee URL | URL 格式校验、可选可达性检查 |
| 在线演示地址 | URL | URL 格式校验 |
| 文本/说明 | 富文本或多行文本 | 最小/最大字数 |
| 截图/图片 | png/jpg 图片 | 格式、数量上限 |
| 其他附件 | 任意文件 | 大小上限（兜底类型） |

> 类型存字典表，新增类型只需「字典加一行 + 前端注册渲染组件 + 后端注册校验处理器」，核心流程不变。

## 四、功能需求列表

### 1. 用户与认证模块

- [ ] F1.1 用户注册（选择角色；教师注册需管理员审核或激活码）
- [ ] F1.2 用户登录 / 登出（JWT Token）
- [ ] F1.3 个人信息维护（姓名、学号/工号、头像、密码修改）
- [ ] F1.4 邀请码机制：教师生成班级邀请码，学生凭码加入班级
- [ ] F1.5 角色权限控制（RBAC，接口级鉴权）

### 2. 班级与课程管理模块

- [ ] F2.1 教师创建班级，生成/刷新邀请码，设置有效期与使用上限
- [ ] F2.2 教师查看班级学生名单，可移除学生
- [ ] F2.3 管理员创建/管理课程模板（多教师复用）
- [ ] F2.4 教师基于课程模板为班级安排教学计划
- [ ] F2.5 学生查看已加入的班级与课程列表

### 3. 步骤（Step）管理模块

- [ ] F3.1 教师按课程拆分步骤，配置标题、描述、要求、参考资料附件
- [ ] F3.2 步骤发布时间、截止时间、权重（总评占比）设置
- [ ] F3.3 交付物要求配置：每个步骤可添加 1~N 个交付项，指定类型、名称、是否必填及类型专属约束；支持增删与排序
- [ ] F3.4 常用交付物模板：保存/复用一组交付项配置（如「文档 + zip + 仓库地址」），减少重复配置
- [ ] F3.5 步骤发布 / 撤回 / 修改（已有提交时修改需提示学生，并可开启允许补交）
- [ ] F3.6 学生查看当前步骤、历史步骤与未来步骤概览
- [ ] F3.7 步骤间依赖关系（前一步提交后才可见下一步，可选）

### 4. 成果提交与进度模块

- [ ] F4.1 按交付项逐项提交：提交页根据步骤交付项动态渲染控件（文件上传 / 文本框 / URL 输入框），必填项校验通过后方可提交
- [ ] F4.2 重复提交保留历史版本；每次提交需覆盖全部必填交付项
- [ ] F4.3 提交完整性校验：缺必填项禁止提交；已批改后补交需教师开启「允许补交」
- [ ] F4.4 文件统一管理：原始文件名、存储路径、大小、MD5，支持预览/下载
- [ ] F4.5 进度状态：未开始 / 进行中 / 已提交 / 已批改 / 逾期
- [ ] F4.6 教师查看全班进度总览（仪表盘：各步骤完成率、缺失交付项名单、逾期名单）
- [ ] F4.7 学生个人进度时间线视图
- [ ] F4.8 教师批改界面按交付项分区块展示学生成果（逐项查看/下载，不合并展示）

### 5. 检查与评分模块

- [ ] F5.1 教师逐个/批量批改：给出分数 + 评语
- [ ] F5.2 评分维度配置（功能完成度、代码质量、文档、创新性等，各占比例）
- [ ] F5.3 按步骤权重自动汇总课程总评成绩
- [ ] F5.4 成绩导出（Excel）
- [ ] F5.5 学生查看成绩与评语，可留言/申诉（可选）

### 6. 大模型辅助模块（DeepSeek API）

- [ ] F6.1 类型感知的 AI 辅助评阅：文档类做内容分析、代码 zip 做结构与质量分析、仓库 URL 做提交记录分析，按交付项输出评阅建议供教师参考（AI 结果仅供参考，不自动计分）
- [ ] F6.2 AI 生成成果要点摘要，辅助批量批改
- [ ] F6.3 AI 辅助生成步骤要求与评分标准（教师建课时）
- [ ] F6.4 学生侧 AI 助教：针对步骤要求答疑（限定课程上下文，可选）
- [ ] F6.5 API 调用管理：Token 用量统计、失败重试与降级（密钥配置见 F8.5）
- [ ] F6.6 大模型服务抽象为独立接口，便于替换其他模型

### 7. 通知与消息模块

- [ ] F7.1 站内消息：步骤发布、截止提醒、成绩发布
- [ ] F7.2 截止日期临近自动提醒（定时任务）
- [ ] F7.3 消息已读管理

### 8. 系统管理模块

- [ ] F8.1 用户管理（禁用/启用、重置密码、角色调整）
- [ ] F8.2 系统参数配置（邀请码规则、附件大小上限、交付物类型字典维护、AI 全局总开关）
- [ ] F8.3 操作日志与登录日志
- [ ] F8.4 数据统计看板（管理员视角：课程数、用户活跃度、AI 调用量）
- [ ] F8.5 大模型服务配置
  - 配置项：服务厂商/模型标识（DeepSeek 为默认）、`baseUrl`、`apiKey`、`model`（如 `deepseek-chat`）、超时时间、重试次数、温度等生成参数、Token/调用限额
  - 支持多套配置并存，指定其中一套为「当前启用」（便于切换模型或密钥轮换）
  - 连通性测试：保存前可发起一次测试调用，验证密钥与网络可用性
  - 启用/停用开关：可一键关闭全部 AI 功能（关闭后 F6 相关入口隐藏或降级为手动操作）
- [ ] F8.6 大模型配置安全要求
  - `apiKey` 加密存储（如 AES），接口返回时脱敏显示（仅后 4 位），禁止明文下发前端
  - 仅管理员可查看/修改配置；教师与学生无任何读取权限
  - 配置变更写入操作日志（记录操作人、时间、变更项，不记录密钥明文）
  - 日志与错误信息中过滤密钥，防止泄露

## 五、非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 常规接口响应 < 1s；支持 500+ 并发学生查询；文件上传异步化 |
| 安全 | BCrypt 密码、JWT 鉴权、接口权限校验、防 SQL 注入/XSS；文件类型白名单 + 大小校验 + 存储路径隔离；大模型密钥加密存储与脱敏 |
| 可扩展 | 交付物类型字典化、大模型服务与配置可替换 |
| 可用性 | 响应式前端，适配 PC 与移动端浏览器；Chrome/Edge/Firefox 主流版本 |
| 数据 | 数据库定时备份；逻辑删除；提交历史版本不覆盖 |

## 六、核心业务流程

1. 管理员开通教师账号 → 教师创建班级并发布邀请码
2. 学生凭邀请码加入班级 → 教师按步骤安排课程任务并配置每步的交付项
3. 每个步骤：教师发布 → 学生按交付项逐项提交 →（AI 分类型初评 +）教师检查评分 → 学生查看反馈
4. 课程结束 → 按步骤权重汇总总评 → 导出成绩

## 七、数据库核心实体（初步）

`用户(User)`、`班级(Class)`、`邀请码(InviteCode)`、`课程(Course)`、`步骤(Step)`、`步骤交付项(StepDeliverableItem)`、`交付物类型字典(DictDeliverableType)`、`文件(File)`、`提交(Submission)`、`提交项(SubmissionItem)`、`评分(Score)`、`消息(Notification)`、`AI调用记录(AiLog)`、`大模型服务配置(AiServiceConfig)`

关键字段：

- `step_deliverable_item`：`id, step_id, name, type_code, required, constraint_json, sort_order`
  - `constraint_json` 存放类型专属约束，如 `{"maxSize": "50MB", "formats": ["pdf", "docx"]}`、`{"minWords": 200}`、`{"urlPattern": "github.com"}`
- `submission_item`：`id, submission_id, deliverable_item_id, type_code, text_value, file_id, url_value`
- `dict_deliverable_type`：`code, name, frontend_component, backend_handler`
- `ai_service_config`：`id, name, provider, base_url, api_key_encrypted, model, params_json, enabled, is_active, timeout, max_retry, created_at, updated_at`

## 八、前端设计要点

- 步骤配置页：交付项列表支持增删排序，按类型动态显示约束配置表单
- 提交页：根据交付项 `type` 动态渲染组件（策略模式：每种类型一个提交控件组件 + 校验规则）
- 批改页：按交付项分区块展示，文件类可预览/下载，URL 类可点击跳转
- 系统配置页：大模型配置列表、脱敏展示、连通性测试、启停与设为当前启用
